# ADRAI v1 coverage ledger

This ledger is a static transcription of the Python prototype's 206 test methods into Haskell-owned behavior contracts. Python was not executed or imported during extraction. A `pythonPath` and `pythonMethod` are historical source anchors, not runtime dependencies; the manifest and all category fragments remain usable after the prototype is deleted.

Each row names one observable behavior, its intended Haskell test, the owning implementation phase, its current coverage state, and structured evidence. `evidence.command` is the Haskell test invocation, `evidence.fixture` identifies the relevant static source or fixture anchor, and `evidence.result` records the reviewed parity result. All three fields are required and substantive. States mean:

- `planned`: the Haskell test is assigned but not implemented.
- `partial`: committed Haskell artifacts cover part of the behavior.
- `covered`: current Haskell tests cover the behavior.
- `installed-haskell-equivalent`: native installed-executable behavior replaces a Python-only entrypoint.
- `not-applicable`: Python packaging metadata has no native Haskell counterpart.

Only the two packaging or module-entrypoint rows from `test_distribution_cli.py` may use `installed-haskell-equivalent` or `not-applicable`; each must explain the translation in `translationNote`. All other rows target ordinary Haskell unit, property, integration, golden, or E2E tests.

Evidence records static source anchors and any Haskell artifacts already providing parity. Evidence can remain useful after source deletion because the behavior contract and Haskell destination are stored in the ledger itself.

Dynamic test data is Haskell-owned. Relevance scenarios belong to `test/support/Adrai/Fixture/Relevance.hs` and use the frozen seed `260729`, while production-scale stress repositories belong to `test/support/Adrai/Fixture/LargeStress.hs`. They must be generated by Haskell test support rather than by running the prototype.

The manifest freezes category counts, allowed values, runtime independence, and deletion policy. Once feature parity and Haskell E2E acceptance are complete, the Python prototype may be deleted without changing or disabling this ledger.

## Audit and closure gate

`stack test adrai:adrai-test --test-arguments=--coverage-ledger-report` prints a deterministic audit. It starts with `schema=adrai/coverage-ledger-audit/v1`, followed by totals, typed gap/state counts, and one sorted tab-separated `gap` row for every non-closure or invalid row. The audit freezes the complete v1 manifest policy: only `covered`, `installed-haskell-equivalent`, and `not-applicable` close rows; `planned` and `partial` always remain gaps. The two translation states are permitted only for the reviewed distribution identities and require a substantive `translationNote`.

The audit also blocks closure when a row has an unknown state, invalid category or row identity, unapproved phase/type/directory, an invalid or missing repository-contained Haskell target, duplicate Python or Haskell identities, or incomplete structured evidence. Policy and fragment schema/count drift are fatal so a manifest edit cannot redefine closure.

`stack test adrai:adrai-test --test-arguments=--require-coverage-ledger-closed` prints the same audit and exits nonzero while any gap exists (or if the row total differs from `expectedTotal`). This is an explicit release gate; the ordinary report command remains informational and succeeds for an open ledger.
